# Участие в разработке NVD Vault

[English](CONTRIBUTING.md) · **Русский**

Спасибо за интерес к проекту! Этот документ описывает как настроить окружение разработки, какие соглашения мы используем и как отправлять изменения.

## Начало работы

```bash
git clone https://github.com/MortalYar/nvd-vault.git
cd nvd-vault
python -m pip install -e ".[dev]"
```

Это установит проект в editable-режиме вместе с `pytest`, `ruff` и `pip-audit`.

## Запуск тестов

```bash
pytest
```

Полный набор тестов проходит за несколько секунд — сетевых вызовов нет (NVD/EPSS/KEV замоканы). Если добавляете функциональность — добавьте к ней тесты.

## Стиль кода

Мы используем [ruff](https://docs.astral.sh/ruff/) и для линтинга, и для форматирования. Перед коммитом:

```bash
ruff check . --fix
ruff format .
```

Обе проверки должны проходить в CI. Конфигурация — в `pyproject.toml`, секция `[tool.ruff]`.

Аннотации типов — в синтаксисе PEP 604: пишите `str | None`, а не `Optional[str]`.

## Сообщения коммитов

Следуем [Conventional Commits](https://www.conventionalcommits.org). Используемые префиксы:

- `feat:` — новая функциональность, видимая пользователю
- `fix:` — исправление бага
- `refactor:` — изменения кода без изменения поведения
- `docs:` — только документация
- `test:` — добавление или обновление тестов
- `ci:` — изменения CI / GitHub Actions
- `chore:` — инструменты, зависимости, обслуживание репозитория
- `style:` — только форматирование (пробелы, кавычки), без изменений логики

Опционально — scope в скобках: `feat(matcher): support pre-release versions`.

Тема коммита — до ~70 символов. Подробности — в теле коммита, если нужно.

## Pull requests

1. **Сначала откройте issue** для нетривиальных изменений — чтобы обсудить подход до написания кода. Для багфиксов issue не обязателен.
2. **Ветвитесь от `main`**, держите PR сфокусированными — одно логическое изменение на PR.
3. **Обновляйте тесты** при изменении кода. Новую функциональность без тестов попросим дополнить.
4. **Обновляйте документацию** при изменении поведения или CLI. README двуязычный (EN + RU) — постарайтесь обновить обе версии, но если не владеете нужным языком — английского достаточно, остальное доделаем.
5. **Дождитесь зелёного CI** перед запросом ревью. Все пять проверок (lint, audit, тесты на Python 3.11/3.12/3.13) должны пройти.
6. **Squash перед мерджем** предпочтителен — это сохраняет историю `main` читаемой.

## Структура проекта

```text
nvd_vault/
├── api/
│   └── bridge.py          # JS ↔ Python IPC для GUI
├── core/
│   ├── nvd_client.py      # HTTP-клиент NVD API 2.0
│   ├── nvd_cache.py       # Дисковый кэш ответов NVD
│   ├── enrichment.py      # Обогащение EPSS + CISA KEV
│   ├── matcher.py         # Сопоставление диапазонов версий CPE 2.3
│   ├── vault_builder.py   # Оркестрация полной сборки
│   └── ...
└── webui/                 # HTML/CSS/JS фронтенд (без сборки)
tests/                     # pytest-сьют
```

Если не уверены где должен лежать новый код — посмотрите на импорты в соседних модулях. `core` — чистый Python без GUI-зависимостей, `api` — слой моста, `webui` — статические ассеты.
